# ADR 0004 — WebSocket transport; Tailscale is not the app protocol

**Status:** accepted  
**Issue:** #5  
**Date:** 2026-09-05

## Decision

The circuit’s application protocol is **messages over WebSocket** (`ws`/`wss`) between holler-client and holler-server.

**Tailscale** (or SSH, or a LAN) may make the TCP path exist. It is **not** Holler auth and not Holler addressing. A client on the tailnet still must `join` with a server-minted token.

## Why not SSH as the protocol

SSH reaches a host. It does not name sessions, carry interrupt as a typed control frame, keep a roster, or let the worker holler back when nobody has a TTY. That is issue #1.

## Consequences

- Server binds a WS listener (localhost / Tailscale IP).
- Reconnect uses the **client credential**, never a fresh join token, unless detached/revoked.
- No `ProxyCommand ssh` in the happy path.
