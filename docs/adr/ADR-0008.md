# ADR 0008 — v1 body is OpenCode via ACP

**Status:** accepted  
**Issue:** #9  
**Date:** 2026-09-05

## Decision

v1 client adapter spawns **`opencode acp`** (JSON-RPC stdio), then `session/new` + `session/prompt`, and streams `session/update` into Holler `reply` / presence.

Interrupt: ACP `session/cancel`, HTTP interrupt fallback (ADR 0005).

Claude Code, Codex, Grok, Hermes, and the rest stay **unchecked** on issue #1 until a config + ACP (or out-of-tree adapter) has run the gate. The **circuit** is harness-agnostic (ADR 0001). OpenCode is the v1 **default command**, not a unique adapter type baked into the server ([ADR 0011](ADR-0011.md)).

## Why ACP

OpenCode already speaks ACP. Claude Code can later sit behind `claude-agent-acp` or a stream-json adapter without changing holler-server. Buzz’s remote agents use the same *idea* (harness command is configurable behind ACP); we implement our own adapter.

What ACP *is* (v1 vs v2, RFDs vs IETF RFCs): [ADR 0012](ADR-0012.md). All protocols in one index: [`docs/protocol/README.md`](../protocol/README.md).
