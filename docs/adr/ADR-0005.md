# ADR 0005 — Interrupt is a control frame; the session survives

**Status:** accepted  
**Issue:** #6  
**Date:** 2026-09-05

## Decision

Walkthrough (diagram): [`docs/protocol/talk.md`](../protocol/talk.md).

`holler interrupt <session>` is **not** a prompt. It is a control message on the circuit.

On the body, v1 maps it to Agent Client Protocol **`session/cancel`**. If that is unsupported, fall back to OpenCode HTTP `POST /api/session/{id}/interrupt`.

The **session stays**. The in-flight **turn** stops. The session must accept a later `prompt`. Nested tool/permission work should cancel with the turn (ACP cascading cancel).

Per-session: interrupting `alpha` must not cancel `beta`.

## Why (Buzz + ACP, not their code)

Buzz treats stop as a **relay message** (`!shutdown`), not kubectl kill (axiom M1: no substrate management channel). Their ACP harness also distinguishes queue / steer / interrupt for mid-turn mentions. We take:

- control is a message, not SSH SIGINT
- interrupt ≠ inject-into-the-prompt (no vendor `steer` in v1)
- we do **not** copy buzz-acp

ACP: `session/cancel` aborts the turn; the session remains promptable. OpenCode restored this via `sdk.session.abort` without closing the ACP session ([opencode#30145](https://github.com/anomalyco/opencode/pull/30145)).

## Busy-turn policy (v1)

- Extra **prompts** while a turn runs: **queue**.
- **interrupt**: cancel current turn; queued prompts stay unless we say otherwise in a later ADR.
