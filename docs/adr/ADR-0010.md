# ADR 0010 — Tokens hashed at rest; TLS on the wire. Tailscale is not involved.

**Status:** accepted  
**Issue:** #11  
**Date:** 2026-09-05

## Decision

Holler does **not** implement its own cipher and does **not** use Tailscale (or SSH, or a LAN) as encryption or as identity.

| What | Pin |
| --- | --- |
| Join secret and client credential, at rest | 256-bit CSPRNG; identifiable prefix (`hlr_…`); **HMAC-SHA-256** of the secret with a server **pepper** stored off the token table. Never store the secret in the clear. |
| Join secret, in memory / CLI | Shown **once** at mint. Never logged. |
| Talk frames | JSON on WebSocket. Confidentiality is **TLS 1.3** on `wss` (AES-256-GCM or ChaCha20-Poly1305). |
| Key exchange on `wss` | TLS 1.3 defaults. If the listener is off a private network, prefer **X25519MLKEM768** (hybrid, RFC 10024) when the TLS stack offers it. |
| Plain `ws` | **Loopback only.** |
| Application auth | Still the minted token → credential (ADR 0003). TLS does not replace `join`. |

Argon2id is **not** the at-rest hash for these secrets: they are 256-bit random, not human-chosen passwords. OWASP Argon2id is for passwords. HMAC-SHA-256 (+ pepper) is what GitHub/Stripe-style API tokens use.

Do not encrypt the token with AES and keep the key next to the ciphertext. That is not hashing.

## Why Tailscale is not in this ADR

ADR 0004 listed Tailscale as one way the **TCP path** might exist, next to SSH and a LAN. That is an underlay. It is not Holler auth, not Holler addressing, and **not Holler encryption**.

Holler does not call Tailscale, does not speak WireGuard, and does not treat a tailnet IP as identity. A client on the same LAN, over a port-forward, or over the public internet still `join`s the same way. If packets happen to ride Tailscale on this homelab, that is the operator’s network, not the protocol.

## Tokens (state of the art, unencumbered)

Join tokens leak into chat and shell history. Mint high entropy; hash at rest.

- **Generate:** 256 bits from the OS CSPRNG (`getrandom` / `crypto/rand`). Prefix so scanners can spot leaks (`hlr_live_…` / `hlr_join_…`).
- **Store:** HMAC-SHA-256(pepper, secret). Pepper lives in the process environment or a file mode 0600, not in the same row as the hash. Lookup by public `token_id` (ADR 0003), compare HMAC in constant time.
- **If we ever mint a short, human-typed join string:** then Argon2id (OWASP 2026 baseline: ~19 MiB, t=2, p=1). v1 does not mint short strings.

Licenses: SHA-256 unpatented; HMAC IETF; Argon2 reference **CC0 or Apache-2.0**. Fits Holler Apache-2.0. No royalty.

## Communication (state of the art, unencumbered)

Do not invent a Holler AEAD or a Noise handshake on the WebSocket.

- **`wss`:** TLS 1.3. Record cipher AES-256-GCM or ChaCha20-Poly1305 (RFC 8439). Libraries: Go `crypto/tls` (BSD), OpenSSL 3 (Apache-2.0), rustls (Apache/MIT/ISC).
- **Public or untrusted path:** prefer TLS group **X25519MLKEM768** (X25519 + ML-KEM-768, RFC 10024 / FIPS 203) so captured traffic is not harvest-now-decrypt-later. Classical X25519-only is acceptable on a private network in v1.
- **`ws`:** localhost only. Refuse plaintext on a non-loopback bind.

ChaCha20, Poly1305, X25519, ML-KEM: public-domain or NIST royalty-free. No GPL-only crypto library in Holler itself (kernel WireGuard is GPLv2; we are not linking it).

## Debug logging (both processes)

Traffic logs must **never** print join secrets, client credentials, connect tickets, or `Authorization` values. Public `token_id`, hostname, session names, and correlation ids are fine.

Levels, default **`none`**. Flag `--debug=none|kind|noisy` and env `HOLLER_DEBUG` (flag wins).

| Level | What you see |
| --- | --- |
| `none` | No debug statements |
| `kind` | High-level: direction, `type`, session/cmd, peer hostname / `token_id`, correlation id. No bodies. |
| `noisy` | Full frames including handshake (`auth`, `hello`, `query`, `ping`/`pong`), with secrets **redacted** (`[redacted]`) |

Same three levels on **holler-server** and **holler-client**. Stories: server epic + [holler-client](https://github.com/Performant-Labs/holler-client).

## Not in v1

- A custom “Holler crypto” protocol
- Treating Tailscale/SSH/LAN as encryption or as identity
- Argon2id as the primary hash of 256-bit tokens
- Logging secrets at any debug level
- Plaintext `ws` on a non-loopback address
