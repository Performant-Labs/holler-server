# ADR 0003 — Join token, then a client credential

**Status:** accepted  
**Issue:** #4  
**Date:** 2026-09-05

## Decision

Pairing is two steps (Tailscale auth-key / device-pairing pattern):

1. **Join token** — minted by holler-server (`holler token mint`). Short-lived, **single-use**, shown once. Stored hashed. Not valid as WebSocket session auth after redeem.
2. **Redeem** — client `holler join --server <url> --token <join>`. Server returns `client_id` + long-lived **client credential** (refreshable). Join token is consumed.
3. **Connect** — every WebSocket uses the credential (first-frame auth or a short-lived connect ticket derived from it). Do not put a long-lived secret in a logged URL query string.
4. **Detach / revoke** — `holler detach` on the client drops the connection and forgets the credential locally. Server `holler client detach <id>` revokes the credential so reconnect fails until a new join token.

## Why not one long-lived join token

Join tokens leak (chat, shell history, screenshots). Cloudflare’s agent WS guidance: short-lived connect material, scope to this server (audience), rotate. A redeemed credential can be revoked without rotating every unused mint.

## CLI (auth)

| Where | Command | Job |
| --- | --- | --- |
| Server | `holler token mint` | Create join token |
| Client | `holler join` | Redeem + persist identity |
| Client | `holler detach` | Disconnect and drop local credential |
| Server | `holler client detach <id>` | Revoke that client |
| Both | `holler status` | Listen/connect health, client_id, session count — **not** the agent roster |
