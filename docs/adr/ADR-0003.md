# ADR 0003 — Join token, then a client credential

**Status:** accepted  
**Issue:** #4  
**Date:** 2026-09-05  
**Updated:** 2026-09-05 (hash algorithm pinned in ADR 0010)

## Decision

Pairing is two steps (short-lived join secret, then a long-lived credential — the usual device-pairing pattern). The **operator noun is `token`**: one durable record per join, listed with the machine that redeemed it. This is not Tailscale and not WireGuard ([ADR 0010](ADR-0010.md)).

1. **Mint** — `holler-server token mint` (alias `create`). Short-lived, **single-use** join secret, shown once. Stored as **HMAC-SHA-256** of a 256-bit CSPRNG secret with a server pepper ([ADR 0010](ADR-0010.md)). Optional `--label` is an operator mnemonic, not the machine name. The record gets a public `token_id` (listable). The secret is not valid as WebSocket session auth after redeem.
2. **Redeem** — client `holler join --server <url> --token <join>`. Client sends **hostname** (OS hostname). Server returns `client_id` + long-lived **client credential** (refreshable). Join secret is consumed. Same `token_id` stays; state becomes `bound`; `machine` is that hostname.
3. **Connect** — every WebSocket uses the credential (first-frame auth or a short-lived connect ticket derived from it). Do not put a long-lived secret in a logged URL query string. Heartbeats refresh `last_seen` and may refresh hostname.
4. **List / delete / ping** — operators work the token record, not a second “client” object:
   - `holler-server token list` — unused and bound rows; **machine hostname** when bound; never the join secret
   - `holler-server token delete <id>` (aliases `rm`, `remove`) — unused: invalidate the secret. Bound: revoke the credential and drop the socket. Reconnect fails until a new mint+join.
   - `holler-server token ping <id>` — application ping/pong on the live WebSocket. Reports hostname + RTT. Unused or disconnected → failure (not ICMP, not SSH, not roster).
5. **Client detach** — `holler detach` on the client drops the connection and forgets the credential locally. `holler-server client list` / `holler-server client detach <id>` are **aliases** of bound-token list / delete.

## Why not one long-lived join token

Join tokens leak (chat, shell history, screenshots). Cloudflare’s agent WS guidance: short-lived connect material, scope to this server (audience), rotate. A redeemed credential can be revoked without rotating every unused mint.

## Why token list is not client list only

Unused join tokens have no machine yet. Redeemed credentials do. Operators list tokens **and the name of the machine using each**. One table, distinct states (`unused` | `bound` | `stale`). Do not print unused secrets next to bound hostnames as if they were the same secret.

## Aliveness (three different questions)

| Command | Question |
| --- | --- |
| `holler-server token ping <id>` | Is **this machine/credential** answering on the wire right now? |
| `holler status` | Is the **circuit** listening / this process connected? |
| `holler-server roster` | Which **sessions** can be hollered at? (presence TTL — ADR 0006) |

`token ping` is a control frame (`ping` / `pong` on the WS). It is not ICMP and not SSH.

## CLI (auth)

| Where | Command | Job |
| --- | --- | --- |
| Server | `holler-server token mint` (`create`) | Create join token; print secret once |
| Server | `holler-server token list` | Unused + bound; machine name; no secrets |
| Server | `holler-server token delete <id>` (`rm`) | Invalidate unused or revoke bound |
| Server | `holler-server token ping <id>` | WS ping/pong; hostname + RTT |
| Client | `holler join` | Redeem + persist identity; send hostname |
| Client | `holler detach` | Disconnect and drop local credential |
| Server | `holler-server client list` / `detach <id>` | Aliases of bound-token list / delete |
| Both | `holler status` | Listen/connect health, client_id, session count — **not** the agent roster |

`--json` on `list` and `ping` (meta-O).
