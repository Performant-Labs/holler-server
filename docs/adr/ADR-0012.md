# ADR 0012 — Body protocol is ACP v1 (RFDs, not IETF RFCs)

**Status:** accepted  
**Issue:** #13  
**Date:** 2026-09-05

## Decision

The **body** (holler-client → local coding agent) speaks **Agent Client Protocol v1**. The **circuit** (holler-server ↔ holler-client) speaks **Holler v1**. Those are different protocols. Do not mix them, and do not wait on ACP v2.

ACP is JSON-RPC 2.0 over **stdio**: the client spawns the agent (`opencode acp`, or another configured command) and calls `session/new`, `session/prompt`, `session/cancel`; the agent streams `session/update`. Same shape as LSP: one host, many agents. Spec and schema: [agentclientprotocol.com](https://agentclientprotocol.com/get-started/introduction), [github.com/agentclientprotocol/agent-client-protocol](https://github.com/agentclientprotocol/agent-client-protocol). Apache-2.0. Governed by Zed and JetBrains.

**Pin ACP v1** (stable). ACP v2 is a **draft** (announced 2026-07-20). Holler v1 must not depend on it.

All protocols Holler uses are listed in one place: [`docs/protocol/README.md`](../protocol/README.md) (GitHub: [#39](https://github.com/Performant-Labs/holler-server/issues/39)).

## RFDs are not IETF RFCs

ACP does **not** have IETF RFCs. It has **RFDs** — **Requests for Dialog** — which they call “ACP’s version of the RFC process”: propose, discuss, record. They are project design notes, not Internet Standards.

JSON-RPC 2.0 itself is the jsonrpc.org spec, not an IETF RFC. JSON is RFC 8259.

**Name collision:** IETF [RFC 8994](https://datatracker.ietf.org/doc/rfc8994/) is also abbreviated “ACP.” That is the **Autonomic Control Plane** for network devices. Unrelated. Do not cite it.

## Not these either

| Thing | Relation |
| --- | --- |
| **Holler v1** | Our WebSocket talk circuit. ACP does not replace it. |
| **MCP** | Agent → tools. ACP is host → coding agent. |
| **ACP v2 draft** | Out of scope for Holler v1. |
| **ACP Registry** | Useful later for discovery; v1 config is an argv, not a registry fetch. |

## Why this ADR

ADR 0008 said “spawn ACP” without saying what that *is*, whether it is standardized, or which version. Implementers would otherwise grab v2 draft types or confuse RFC 8994.

## Consequences

- Interrupt maps to ACP v1 `session/cancel` (ADR 0005). HTTP interrupt remains a configured fallback, not a second body protocol.
- New harnesses stay config + ACP v1 (or an out-of-tree binary that speaks ACP v1) — ADR 0011.
- Bumping to ACP v2 is a future ADR, after v2 is stable.
