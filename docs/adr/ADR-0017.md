# ADR 0017 — Attach mode: far box may already own the body (Herdr + OpenCode)

**Status:** proposed (accept when [epic #254](https://github.com/Performant-Labs/holler-server/issues/254) lands)
**Issue:** #18
**Date:** 2026-09-07

**Companion ADR:** [holler-client#6](https://github.com/Performant-Labs/holler-client/issues/6) (ADR 0005).
**Epic:** [#254](https://github.com/Performant-Labs/holler-server/issues/254).

## Context

[ADR 0001](ADR-0001.md) / [ADR 0002](ADR-0002.md) / [#1](https://github.com/Performant-Labs/holler-server/issues/1) said: hub runs Herdr + holler-server; far box runs holler-client + harness and **does not run Herdr**. v1 implemented that as **spawn-and-own**: `holler run` execs `opencode acp`, ACP `session/new`, and `detach`/`shutdown` tears down that child.

That cut is still valid for a Herdr-free box. It is the wrong cut when the operator already has OpenCode in a Herdr pane on the far machine and wants that *same* session on the circuit.

Two parents cannot both own the process:

- Herdr owns the PTY and the OpenCode TUI in the pane.
- v1 holler-client owns a *second* `opencode acp` child and kills it when the client exits.

Result: either a second invisible session, or the session the human is watching dies when Holler detaches.

## Decision

1. **Spawn-and-own remains the default** (`mode = "spawn"` / omitted). ADR 0002 is not revoked. Herdr-free far boxes keep working.
2. **Attach mode is a first-class second body transport.** The far box may already run Herdr and OpenCode. holler-client joins the circuit and drives the *existing* OpenCode session over that process's HTTP control surface. It is **not** the parent of OpenCode. `detach` / client exit / WS drop **must not** kill or `session/new`-replace the attached session.
3. **Holler is still not a multiplexer.** Do not type into the Herdr PTY (`herdr pane send-keys`, ANSI stuffing). Interrupt stays a control frame mapped to OpenCode HTTP interrupt / ACP cancel. No pane streaming on the Holler wire.
4. **Address sessions, not hosts** ([ADR 0007](ADR-0007.md)) still holds. The Holler session *name* (`alpha`) is the circuit address. The OpenCode `ses_…` id is a body-side locator, advertised on presence so the roster can show attach vs spawn without changing who `say alpha` talks to.
5. **No Holler protocol version bump required** if presence already has an extension object. If the current `presence` frame cannot carry `mode` + `harness_session_id` without breaking v1 decoders, add those fields as *optional* keys (unknown-key ignore is already the v1 rule). Do not mint Holler v2 for this.
6. **Do not run `holler run` as the foreground command of the OpenCode pane.** Operator layout:

```
remote:  Herdr pane  → OpenCode TUI          (Herdr + OC own this)
         holler run --config attach.toml     (sidecar / other pane / daemon)
hub:     holler-server + `say` / `interrupt` (Herdr pane optional)
```

## Consequences

- Server docs (`README`, `docs/protocol/talk.md`, brief #1) gain an attach topology next to the Herdr-free one. The original success test stays; attach gets its own gate.
- Roster/status may show `mode: attach` and the harness session id. Routing is still by Holler session name.
- `holler support` grows `attach` / `opencode-http` as features the client can confirm.
- Out of scope here: daemonizing spawn-mode children, Claude/other attach, sending keys into a PTY.
