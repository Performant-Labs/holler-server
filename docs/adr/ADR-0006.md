# ADR 0006 — Presence is status

**Status:** accepted  
**Issue:** #7  
**Date:** 2026-09-05  
**Updated:** 2026-09-05 (`token ping` is not roster)

## Decision

The roster is **conversational availability**, not “is sshd up” and not “did we attach a TUI.”

holler-client heartbeats. Each advertised session has a TTL. When heartbeats stop, the server marks the client/session stale and drops it from `holler-server roster` after TTL (bounded wrong dot, never an indefinite one — Buzz I3, not their code).

`holler status` is **who this process is** (and, with a target, who that peer is) — same document for server and client (ADR 0009). `holler support` is **do you support X**. `holler-server roster` is **who can be hollered at**. `holler-server token ping` is **is this bound machine answering** (ADR 0003).

## Consequences

- Do not scrape remote process tables over SSH for the roster.
- A client can be connected with zero sessions (show in status, empty roster).
- Gate requires both sessions visible on roster before `say`.
