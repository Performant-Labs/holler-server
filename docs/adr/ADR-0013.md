# ADR 0013 — Rust, because we want the official ACP SDK

**Status:** accepted  
**Issue:** #14  
**Date:** 2026-09-05

## Decision

Holler (server and client) is implemented in **Rust**.

The body hop speaks **ACP v1** (ADR 0012). The **official** client/agent SDK for that protocol is the Rust crate [`agent-client-protocol`](https://github.com/agentclientprotocol/rust-sdk) (Apache-2.0, same org as the spec). We use that crate, **v1 types only** — not the ACP v2 draft.

Do not implement Holler in Go. Community Go ACP libraries exist; they are not the spec’s SDK. Tracking them is the same class of maintenance ADR 0011 refused (a Holler release every time a vendor CLI drifts).

Stack: `cargo`, Tokio, rustls, `cargo test` on Linux / macOS / Windows.

## Why not Go

| | Rust | Go |
| --- | --- | --- |
| ACP | Official SDK | Unofficial (e.g. coder/acp-go-sdk) |
| Drift vs Zed/JetBrains schema | Their problem | Ours |
| Fit | CLI daemon + stdio subprocesses + static binary | Same, slightly faster to type |

Holler is not CPU-bound. The reason for Rust is **ACP**, not “no GC.” Herdr is also Rust; that is convenient, not the deciding vote.

## Consequences

- First code is the fail-fast canary ([#41](https://github.com/Performant-Labs/holler-server/issues/41)): `cargo test`.
- Client ACP driver ([holler-client#26](https://github.com/Performant-Labs/holler-client/issues/26)) depends on `agent-client-protocol` v1.
- Toolchain: [`docs/dev-env.md`](../dev-env.md).
